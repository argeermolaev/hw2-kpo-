# Модуль «ПОС» (Преподавательская оценка студентов)

Учебный проект, демонстрирующий применение Domain-Driven Design (DDD), чистой архитектуры и паттернов GoF.

##  Архитектура

Выбрана Ports and Adapters.
Зависимости направлены строго внутрь (стрелка вправо):

`ConsoleUI` -> `Infrastructure` -> `Application` -> `Domain`

*   **Domain**: Ядро системы. Сущности, объекты-значения, инварианты, доменные сервисы. Не зависит ни от чего.
*   **Application**: Сценарии использования (Use Cases). Оркестрирует работу домена и репозиториев. Содержит фабрики и интерфейсы портов.
*   **Infrastructure**: Адаптеры (реализации репозиториев). В текущей версии — In-Memory.
*   **ConsoleUI**: Точка входа. Настройка DI-контейнера (Composition Root) и консольное меню.

## DDD (Domain Drived Design) 
### Ubiquitous Language (Единый язык)
*   **Студент (Student)** — пользователь, которому выставляются оценки.
*   **Критерий (Criterion)** — правило оценки (имеет максимальный балл и вес).
*   **Оценка (Evaluation)** — факт выставления балла студенту по критерию.
*   **Итог (Grade)** — вычисляемый результат на основе оценок и весов.

### Карта DDD
*   **Entities (Сущности)**: `Student`, `Criterion`, `Evaluation`. Имеют идентификатор (`Guid`) и жизненный цикл.
*   **Value Objects (Объекты-значения)**: `Score`, `Weight`. Неизменяемы, не имеют ID, инкапсулируют логику валидации (например, балл не может быть больше максимума).
*   **Инварианты**: 
    *   `Score` всегда в диапазоне `[0, MaxScore]`.
    *   `Weight` всегда в диапазоне `[0, 1]`.
    *   Оценку можно выставить только существующему критерию.
*   **Domain Service**: `GradeCalculator`. Вычисляет итоговый балл, так как правило не принадлежит одной сущности.
*   **Repositories (Порты)**: `IStudentRepository`, `ICriterionRepository`, `IEvaluationRepository`. Абстракции хранения данных, вынесенные в Domain.

##  Паттерны GoF

1.  **Порождающий: Factory Method (`EvaluationFactory`)**
    *   *Где*: В слое Application.
    *   *За что отвечает*: Инкапсулирует сложную логику создания оценки (генерация `Guid`, установка текущей даты, валидация балла через Value Object).
2.  **Структурный: Facade (`Menu` в ConsoleUI)**
    *   *Где*: Слой представления (UI).
    *   *За что отвечает*: Предоставляет простой интерфейс для консоли, скрывая сложность работы с DI-контейнером и множеством Application-сервисов.
3.  **Поведенческий: Strategy (`IGradeCalculationStrategy`)**
    *   *Где*: В домене (или Application).
    *   *За что отвечает*: Позволяет легко менять алгоритм подсчета итогового балла (например, взвешенная сумма или средний балл) без изменения класса `GradeCalculator`.

*   Использовался для шаблонного кода некоторых классов и unit-тестов, проверки кода на соответствие принципам DDD и наличие паттернов GoF и отладке консольного меню.
